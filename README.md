Скрипт `install_xray.sh` — решение «всё в одном» (All-in-One) для автоматизированного развертывания и администрирования многопротокольного защищенного сетевого шлюза (**VLESS Reality SelfSteal**, **VLESS XHTTP**, **Hysteria 2** и **Telegram MTProto Telemt**) на Linux VPS/VDS с передовой архитектурой **SelfSteal**.

Проект разработан для организации надежных зашифрованных каналов связи, максимальной защиты от активного сетевого пробинга (DPI/TSPU), снижения задержек (Jitter/Latency), а также централизованного управления конфигурациями устройств. Архитектура изолирована и безопасна для параллельной работы с другими сетевыми комплексами (например, **AntiZapret**).

## 🛠️ Технологический стек (Tech Stack)

- **Языки и автоматизация**: Bash 5.x, Python 3 (демон динамических конфигураций и генератор подписок)
- **Веб-сервер и обратный прокси**: Nginx (слушает локальный Unix-сокет `/dev/shm/nginx.sock` с PROXY protocol, обслуживает ACME-челленджи на 80/tcp, проксирует XHTTP `/api/v2/stream/` в сокет `/dev/shm/xrxh.socket` и отдает локализованный сайт-камуфляж)
- **Транспортные ядра**:
  - **Xray-core**: VLESS Reality на порту 443 TCP со сквозным SelfSteal-фолбэком в Nginx через Unix-сокет; VLESS XHTTP на защищенном Unix-сокете `/dev/shm/xrxh.socket` за Nginx без накладных расходов loopback
  - **Hysteria 2**: UDP QUIC на порту 20443 с Port Hopping `20000:50000` (порт `443/udp` принудительно заблокирован для предотвращения троттлинга DPI)
- **Telegram MTProto Proxy**: [Telemt](https://github.com/telemt/telemt) (написан на Rust, ~10-15 МБ RAM, zero-copy socket I/O, встроенная Fake-TLS маскировка под Cloudflare на порту 8444 TCP)
- **Поддерживаемые ОС**: Debian 11 / 12 / 13, Ubuntu 20.04 / 22.04 / 24.04 (x86_64, aarch64)
- **Ядро и Сеть**: Xanmod Kernel (x64v1-v3), TCP BBR, ZRAM (LZ4) + Disk Swap, PMTU MSS Clamping, Systemd/Journald Tuning
- **Двухканальная оптимизация исходящих маршрутов (Dual-Egress Routing)**: Cloudflare WARP (WireGuard) для AI-платформ и стриминга + Psiphon (Docker SOCKS5) для геозависимых сервисов Google & Gemini
- **Камуфляж и SelfSteal**: Мультиязычный enterprise-сайт в `/var/www/html` с автоопределением локации VPS (NL, DE, FI, PL, TR, EN), анти-DPI санитизацией метатегов и динамической солью

## 📋 Требования к серверу (Prerequisites)

1. **Операционная система**: Чистая Debian 11/12/13 или Ubuntu 20.04/22.04/24.04 с правами `root`.
2. **Домен и DNS**: Зарегистрированный домен с настроенной **A-записью**, указывающей на публичный IPv4-адрес вашего сервера (например, `sub.domain.com -> 1.2.3.4`).
3. **Сетевые порты**:
   - `80/tcp` — получение и автоматическое продление TLS-сертификатов Let's Encrypt / Certbot, 301 HTTPS редирект.
   - `443/tcp` — единый защищенный шлюз: VLESS Reality (SelfSteal в Nginx) + VLESS XHTTP (по пути `/api/v2/stream/` через Nginx) + подписки `/sub/` + сайт-камуфляж.
   - `20443/udp` — высокоскоростной шлюз Hysteria 2 (QUIC). Стандартный порт `443/udp` заблокирован (DROP) для предотвращения замедления операторами связи.
   - `20000:50000/udp` — диапазон динамических портов (Port Hopping) для Hysteria 2 с автоматическим iptables/nftables редиректом на `20443`.
   - `8444/tcp` — ⭐️ **Лучший и оптимальный порт для Telegram MTProto (Telemt Fake-TLS)**. Стандартизированный порт Cloudflare, исключающий любые коллизии.

## 📐 Архитектура трафика (Dual-Egress Architecture)

```text
               ┌────────────────────────────────────────────────────────┐
               │              Входящий трафик клиентов                 │
               └───────────────────┬────────────────────────────────────┘
                                   │ (443 TCP / 20443 UDP / 8444 TCP)
                                   ▼
        ┌──────────────────────────────────────┬────────────────────────┐
        │        Xray-core / Nginx             │  Telemt (MTProto TLS)  │
        │  (VLESS Reality, XHTTP, SelfSteal)   │   (Порт 8444 TCP)      │
        │  & Hysteria 2 (Порт 20443 UDP)       │                        │
        └──────────────────┬───────────────────┴───────────┬────────────┘
                           │                               │
 ┌─────────────────────────┼─────────────────────────┐     │ (Прямой туннель к DC)
 │ (Прямой веб-трафик,     │ (AI-сервисы, Spotify,   │     ▼
 │  YouTube 4K, чекеры IP) │  TikTok, соцсети)       │ ┌─────────────────────────┐
 ▼                         ▼                         ▼ │  Telegram Data Centers  │
┌──────────────────┐    ┌────────────────────┐    ┌─── │  (Прямой защищенный     │
│  DIRECT Outbound │    │  Cloudflare WARP   │    │    │   доступ к мессенджеру) │
│  (Чистый IP VPS) │    │  (WireGuard tun)   │    │ └─────────────────────────┘
└──────────────────┘    └────────────────────┘    └───┘
```

## ✨ Ключевые возможности

* 🪞 **Архитектура VLESS Reality SelfSteal (Порт 443 TCP)**: Единый порт 443 обслуживает аутентифицированный VLESS-трафик и полноценный веб-сайт. Xray слушает входящий трафик 443 TCP: сессии Reality терминируются ядром с ускорением `xtls-rprx-vision`, а неавторизованные запросы и сканеры цензуры (DPI/ТСПУ) бесшовно передаются через PROXY protocol v1 на локальный Unix-сокет Nginx (`/dev/shm/nginx.sock`).
* 🛡️ **Протокол VLESS XHTTP за Nginx (Порт 443 TCP, путь `/api/v2/stream/`)**: Передовой транспорт поверх HTTP/2 на выделенном Unix-сокете (`/dev/shm/xrxh.socket`). Nginx принимает HTTPS-трафик на порту 443 и проксирует поток в Xray без оверхеда сетевого стека. Устаревший отдельный порт 8443 полностью упразднен. Поддерживается рандомизированный паддинг пакетов (`xPaddingBytes: 100-1000`) и полная совместимость с CDN (Cloudflare).
* ⚡ **Hysteria 2 (Порт 20443 UDP / Port Hopping 20000-50000)**: Протокол на базе UDP/QUIC (BBR/Brutal) для сверхнизких задержек и стабильности в мобильных сетях. Порт `443/udp` принудительно заблокирован (`DROP`), что предотвращает избирательное глушение и троттлинг UDP со стороны ТСПУ/DPI.
* ✈️ **Telegram MTProto прокси на базе Telemt (Лучший порт 8444 TCP)**:
  * **Прямой доступ в мессенджер в 1 клик**: Работает на всех устройствах (iOS, Android, macOS, Windows) без необходимости держать постоянно включенным общий системный туннель.
  * **Почему именно порт 8444 является лучшим**:
    1. *Идеальная совместимость без конфликтов*: порт `443` занят связкой VLESS Reality SelfSteal + XHTTP + Nginx, а `20443` — Hysteria 2.
    2. *Оптимальный выделенный HTTPS-порт*: порт `8444` гарантирует отсутствие конфликтов с системными веб-сервисами и другими протоколами.
    3. *Устойчивость к сигнатурной классификации*: в сочетании с Fake-TLS и SNI `www.cloudflare.com` трафик на порту 8444 стандартизирован под типовой HTTPS-трафик к CDN Cloudflare и не подвергается эвристическим сбросам соединений.
  * **Zero-overhead архитектура (Rust)**: Бинарник скомпилирован на Rust, потребляет символические 10–15 МБ RAM, использует системный epoll/kqueue и подключается напрямую к дата-центрам Telegram без лишних транзитных звеньев.
  * **Fake-TLS маскировка**: Защита метаданных и сигнатур за счет префикса `ee...` и упаковки в стандартизованный TLS ClientHello.
  * **Интерактивная выдача**: Автоматическая генерация ссылок `tg://proxy?...`, QR-код в консоли (`xry` ➔ `1` ➔ клавиша `T`) и персональная карточка подключения на веб-странице подписки `/sub/UUID`.
* 📱 **Сервер динамических конфигураций и умного раздельного туннелирования (Base64 / JSON / YAML / XKeen)**:
  * Персональная ссылка подписки (`https://ваш-домен.com/sub/UUID`).
  * **Автороутинг для Happ и INCY**: Автоматическая инъекция HTTP-заголовков (`routing`, `autorouting`) и служебных метатегов для бесшовной загрузки профилей умной маршрутизации напрямую из репозитория [mvrvntn/routing](https://github.com/mvrvntn/routing).
  * **Мультиформатность на лету**:
    * Стандартная подписка (Base64) для **Happ**, **INCY**, **Shadowrocket**, **v2rayNG**, **NekoBox**, **Hiddify**, **FoXray**.
    * `?format=singbox` — скомпилированный конфиг **Sing-Box** со встроенными удаленными `.srs` правилами (`category-ru`, `discord-ip`, `category-ads`).
    * `?format=clash` / `?format=mihomo` — готовый YAML для **Mihomo**, **Clash Verge Rev**, **Flclash**, **Mihomo Party** с правилами и базами `geox-url`.
    * `?format=xray` — полный JSON для ядра **Xray** с `routing.rules`.
    * `?format=xkeen` — оптимизированная конфигурация для роутеров **Keenetic** (пакет `xkeen` / Entware).
  * Поддерживает `server-address-resolve-enable: 0` для предотвращения DNS deadlock в TUN-режиме на всех версиях клиентов.
* 🧭 **Динамические профили маршрутизации клиентов (Routing Profiles)**:
  * **Default**: Умное разделение трафика (прямой доступ к локальным ресурсам РФ на максимальной скорости и защищенный транзит для внешних международных узлов).
  * **Relocant**: Для специалистов за рубежом (мировой трафик напрямую с устройства, а доверенные сервисы РФ — через защищенный шлюз).
  * **Whitelist**: Строгий режим белых списков РФ.
  * **Off**: 100% трафика направляется через туннель без разделения.
* 🌐 **Оптимизация доступа к сервисам Google & Gemini через Psiphon**:
  * Изолированный Docker-клиент Psiphon с локальным SOCKS5-прокси.
  * Автоопределение локации VPS: если сервер находится в стране без поддержки Gemini (например, Турция `TR`, РФ `RU`), скрипт автоматически переключает выход на Германию (`DE`).
  * Полный охват сессии Google (`gemini.google.com`, `aistudio.google.com`, `googleapis.com`, `gstatic.com`, `googleusercontent.com`, `google.com`) для предотвращения расщепления сессий `IP: A ≠ B`.
  * Фильтрация UDP для принудительного переключения браузеров с QUIC на надежный протокол TCP.
  * Трафик YouTube (`youtube.com`, `googlevideo.com`) направляется напрямую (`DIRECT`), предотвращая просадку скорости видео.
* 🌀 **Селективная маршрутизация через Cloudflare WARP**:
  * **Smart (Рекомендуемый)**: Направляет через Cloudflare только AI-сервисы (ChatGPT, Claude, Perplexity, Grok, ElevenLabs), Spotify (включая стриминговые CDN Akamai/pscdn), TikTok и соцсети.
  * **Full**: Направляет весь исходящий трафик сервера через Cloudflare.
  * Защита от утечек IPv6 (`domainStrategy: UseIPv4`), сброса NAT (`PersistentKeepalive = 25`) и автообновление баз маршрутизации геораспределения через cron.
* 🧅 **Встроенный шлюз Tor (.onion SOCKS5)**: Прозрачное проксирование `.onion`-доменов через локальный Tor-демон (`127.0.0.1:9050`) без необходимости открывать Tor Browser.
* 🎯 **Адаптивная автокалибровка маршрутов (Auto-Tune)**: Сканирование доступности сервисов с прямого IP конкретного сервера за 2 секунды. Конфигурация Xray адаптируется под VPS: если сервис (например, Google в Нидерландах или ChatGPT в Германии) доступен напрямую — он идет через `DIRECT` на максимальной скорости гигабита. В туннели (WARP/Psiphon) направляются только те ресурсы, к которым ограничена прямая связность на данном хостинге.
* 💾 **Резервное копирование и восстановление (Backup & Restore)**: Создание полных снепшотов конфигураций (Xray, Hysteria 2, Nginx, SSL-сертификаты, Psiphon, Tor, Telemt, службы systemd) с ротацией 7 последних копий и быстрыми командами `--backup` / `--restore`.
* ⚙️ **Поддержка оптимизированного ядра Jolymmiles/Xray-core**: Бесшовное переключение между официальным upstream XTLS и форком [Jolymmiles/Xray-core](https://github.com/Jolymmiles/Xray-core) (поддержка TCP Brutal v2, отсутствие сбросов carrier при EPERM сокетов ядра, WebSocket delay-dial патчи и валидация RemnaNode). Автоматическое получение свежих релизов через пункт 9 меню или `xry --update-core`.
* 🧹 **Очистка и аудит диска (Express Disk Audit & Cleanup)**: Безопасное освобождение 2–5 ГБ дискового пространства в 1 клик: очистка кэшей APT, сжатие системных журналов journald (до 50M), удаление архивных ротированных логов, временных файлов, кэша Docker и старых ядер Linux (с защитой текущего рабочего ядра `uname -r` и обновлением GRUB). Доступно в меню диагностики (пункт 7 ➔ 6/7) и флагами `--clean-disk` / `--disk-analysis`.
* 🧪 **Углубленная диагностика и медиа-аудит (ipregion)**: Встроенный аудит портов, служб и SSL, а также углубленное тестирование доступности AI (ChatGPT, Claude, Gemini) и стримингов (Spotify, Netflix, Disney+, TikTok, YouTube) через прямой IP, интерфейс Cloudflare WARP и SOCKS5 Psiphon.
* 🛡️ **Многоуровневая сетевая безопасность**: Фильтрация нежелательного рекламного контента, изоляция уязвимых сетевых портов (25, 445 и др.), P2P-трафика и защита от вредоносных сетевых узлов на уровне ядра Xray.
* 🎭 **Адаптивный камуфляж (Decoy / Selfsteal)**: Реалистичный enterprise веб-сайт на Nginx в `/var/www/html` с автоопределением языка по стране VPS, очисткой подозрительных метатегов и внедрением уникального токена сборки против фингерпринтинга.
* ⚡ **Комплексная оптимизация VPS**:
  * **Гибридная память**: ZRAM (50-60% RAM с LZ4) + 2GB Disk Swap (с защитой свободного диска $\ge$ 4GB).
  * **Сетевой стек**: Тюнинг `sysctl` (`fs.file-max=67M`, BBR, TCP Fast Open, динамические буферы по `_PHYS_PAGES` до 32MB).
  * **Мобильный KeepAlive**: `tcp_keepalive_time = 60s` для предотвращения сбросов сессий в мобильных сетях.
  * **Многопоточность (RPS)**: Автоматическое распределение очередей сетевых карт по всем ядрам CPU.
  * **PMTU Fix**: Автоматический TCP MSS Clamping против фрагментации пакетов.
  * **Персистентный Port Hopping**: Автоматическое внедрение NAT-таблицы (`20000:50000/udp -> 20443`).
  * **Ядро Xanmod**: Автоматическая сборка под процессорную архитектуру (v1-v3).

## 🏷️ Формат профилей и обозначений

При импорте конфигурации в клиентское приложение или подключении формируются следующие профили:

| Протокол | Формат имени в клиенте | Порт и транспорт | Назначение |
|---|---|---|---|
| **VLESS XHTTP** | `🇳🇱🛡️ VLESS-XHTTP` | `443/tcp` (XHTTP, `/api/v2/stream/` через Nginx) | Приоритетный профиль: защита от DPI, рандомизация пакетов, совместимость с CDN |
| **VLESS Reality** | `🇳🇱🪞 VLESS-Reality` | `443/tcp` (Reality SelfSteal, fallback Nginx) | Высокоскоростной профиль с маскировкой под подлинный веб-сайт сервера |
| **Hysteria 2** | `🇳🇱⚡ Hysteria2` | `20443/udp` (QUIC, hopping `20000:50000`) | Минимальные задержки и высокий CPS в нестабильных мобильных сетях (443/udp DROP) |
| **Telegram MTProto** | `✈️ Telegram MTProto` | `8444/tcp` (Telemt Fake-TLS) | ⭐️ Прямое выделенное подключение Telegram на оптимальном альтернативном HTTPS-порту |

## 🤝 Совместимость с локальными шлюзами (AntiZapret)

Проект спроектирован для безопасного и изолированного сосуществования с **AntiZapret** на одном хосте:

1. Инсталлятор автоматически определяет наличие правил и служб AntiZapret (`openvpn-server@antizapret-*`, `knot-resolver`, таблицы iptables).
2. UFW отключается во избежание конфликта цепочек.
3. Необходимые порты Xray, Nginx и Hysteria (`80, 443 TCP`, `8444 TCP` и `20443, 20000:50000 UDP`) вставляются на **1-ю и 2-ю позиции цепочки `INPUT`**, что предотвращает их попадание в ловушку `antizapret-block`.
4. Внутренние службы AntiZapret, таблицы маршрутизации и локальный DNS остаются полностью работоспособными и автономными.

## ❓ Troubleshooting & Часто задаваемые вопросы (FAQ)

### 1. Почему Google и Gemini требуют Psiphon, а не WARP?
* Google классифицирует диапазоны Cloudflare WARP как принадлежащие РФ независимо от физической локации эндпоинта WARP. Попытка направить Gemini через WARP приводит к ошибке *«Не поддерживается в вашей стране»*.
* Psiphon имеет чистые европейские пулы IP с высокой репутацией для Google. При этом скрипт блокирует UDP для доменов Google, принуждая браузеры мгновенно откатываться с QUIC на TCP.

### 2. Что делать, если Google выдает капчу при активном Psiphon?
* Выполните ротацию выходного IP в консоли сервера:
  ```bash
  vps-psiphon rotate
  ```
  Или через меню `xry` -> пункт `4` (Маршрутизация) -> пункт `15` («Ротация IP Psiphon»).

### 3. Как переключить сервер на маршрутизацию для специалистов за рубежом?
* Если ваш сервер находится на территории РФ или вы находитесь за рубежом и хотите иметь быстрый доступ к российским веб-ресурсам с геолокационными ограничениями (Госуслуги, банковские порталы, локальные сервисы):
  * Запустите `xry` -> пункт `4` (Маршрутизация) -> пункт `10` («Сменить профиль маршрутизации»).
  * Выберите профиль **`2` (Relocant)**. Весь мировой интернет пойдет напрямую с вашего устройства, а трафик РФ — через ваш сервер.

### 4. Ошибка при получении сертификата Certbot ("Порт 80 занят")
* **Причина**: На сервере уже активен другой веб-сервер (Nginx, Apache, Caddy).
* **Решение**: Инсталлятор автоматически временно останавливает Nginx на момент выпуска standalone-сертификата и перезапускает его сразу после завершения процедуры.

### 5. Соединение Hysteria 2 не устанавливается на облачном VPS
* **Причина**: В панели управления облачной инфраструктуры (Security Groups / Firewall) не открыты входящие UDP-порты.
* **Решение**: Добавьте разрешающие входящие правила для `20443/udp` и диапазона `20000:50000/udp` (порт `443/udp` принудительно заблокирован против DPI-троттлинга).

### 6. Как обновить скрипт и применить последние исправления?
* Запустите `xry`, выберите пункт **`9`** («Обновить скрипт с GitHub / зеркал и применить новые фиксы»).

### 7. Почему для Telegram MTProto выбран именно порт 8444 и почему он лучший?
* **Исключение конфликтов**: Стандартный HTTPS-порт `443` занят связкой VLESS Reality SelfSteal + XHTTP + Nginx, а `20443` — под Hysteria 2.
* **Оптимальный выделенный HTTPS-порт**: Порт `8444` исключает конфликты и обеспечивает надежную изоляцию трафика MTProto от основных протоколов сервера.
* **Стандартизация Fake-TLS**: В связке с маскировкой Fake-TLS (SNI `www.cloudflare.com`) трафик MTProto на порту 8444 стандартизирован под типовой защищенный HTTPS-трафик к Cloudflare, предотвращая эвристический сброс соединений по специфичным сигнатурам протокола Telegram.
* **Нативная поддержка**: Все официальные клиенты Telegram на iOS, Android, macOS, Windows и Linux без каких-либо затруднений устанавливают соединение по порту 8444.

### 8. Как настроить Telegram изолированно от основного туннеля?
* В консоли сервера вызовите `xry` ➔ пункт **`16`** ➔ пункт **`1`** («Показать ссылку подключения и QR-код для Telegram»).
* Либо в пункте **`1`** главного меню нажмите клавишу **`T`** для моментального вывода QR-кода Telegram.
* Также прямая кнопка подключения доступна на вашей веб-странице подписки (`https://ваш-домен.com/sub/UUID`). Кликните по ссылке формата `tg://proxy?server=...&port=8444&secret=ee...` — приложение Telegram мгновенно откроется и предложит добавить прокси.
